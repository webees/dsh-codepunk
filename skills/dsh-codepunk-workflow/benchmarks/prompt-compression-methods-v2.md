## ① 外部技巧（6 条）
| # | 技巧 | 适用 | 风险 |
|---|------|------|------|
| T1 | 追求「最小高信号 token 集」而非最短：逐条问"删掉它行为是否改变" | 任何预设的删改判据 | 把"短"当目标 → 误删承重约束，行为漂移 |
| T2 | 例外/边界优先于流程复述（"think like the model"）：模型已知的通用流程不写，只写何时不适用 | 通用能力已内化的段落 | 私有约定（阶段号、目录名、门闩）不可删 |
| T3 | 渐进披露：低频细则移入 references/，主提示只留索引＋**可判定的触发条件** | 长尾细则、评分表、模板 | 多一跳读文件；触发条件写不清 → 召回失败，比冗余更贵 |
| T4 | 结构分隔符＋稳定前缀（分块标签、长重复内容前置） | 多角色/多阶段预设；利于前缀缓存 | 标签自身占 token；层级过深反降遵循率 |
| T5 | 用 1-2 个短例替代形容词（"要简洁专业"→ 示例） | 输出格式、汇报模板 | 示例被当内容照抄（过拟合）；示例可能比描述更贵 |
| T6 | 外部化记忆（结构化笔记/compaction）：状态写文件，提示只留"写在哪、读哪" | 长程多轮 agent | 陈旧笔记污染后续推断 |

## ③ dsh-codepunk（570KB）是否还有安全精简空间
**结论：没有成规模的安全精简空间。**
1. D074-D081 打磨后密度已极高（仓内自查记录：零弱修饰／零重复长句／零双空行）。
2. 剩余体量主体在 references/ 细则，属 T3 **已实施**的按需披露，并非常驻上下文——压它不省运行时 token。
3. 唯一可动项：把低频模板再下沉一层，收益 <10KB，却引入召回失败风险，违反 D074「压缩先保召回」。
4. 建议改向：停止体量压缩，转做**装载路径审计**（确认哪些文件真正常驻、哪些只是磁盘占用）。
