# 输出与通信纪律（references/output-discipline.md）

> **D074 上下文纪律 / D075 消息纪律 / D076 token 经济学** 三条全员适用纪律的完整细则（SKILL §④ 只留指引）。R11 为承重条目，本文件是其细则。

## D074 上下文纪律（借鉴 Anthropic 上下文工程）

1. **证据只回** `command + exit_code + log_ref`，拒绝整段 stdout；大输出 head/tail 截断。
2. **小组汇报 ≤1500 token 摘要**；主会话巡检读 `summary`/`progress`，不回传大日志。
3. **主会话每轮收尾把已消化巡检记录压缩为一行结论**，防陈旧消息与上下文堆积误导（R12 同源）。

## D075 消息纪律

1. **首行 = 可执行结论**（动作/命令先行）；末行给下一件 2 分钟内可做的事；发送前**首末行双读**（下一步 + 刚发生了什么）。
2. **多步任务编号 ≤5 项**（超则拆 now/later）+ **工具清单替叙事**（有 todo 工具就用它 restate，不复述全计划）。
3. **禁前导/复述/寒暄**（"Great question" 式删除）；保留真实不确定 hedge，删无信息 hedge。
4. **安全先于简洁**：破坏性动作先确认再执行。
5. **调试螺旋防空转**：三轮仍 broken → 停改码，点名可疑假设 + 问一个诊断问题。

## D076 token 经济学（借鉴 caveman MIT）

1. **禁自造缩写与箭头**（cfg/impl/req/fn、`→`）——零节省且伤解码；中文短词单 token 不受影响，英文字段禁缩写。
2. **保护清单（绝不压缩）**：术语/代码/API 名/CLI 命令/错误串逐字保留；数字/日期精确；**never drop not/no/only/except**（翻转语义代价大于节省）。
3. **Auto-Clarity 豁免**：安全警告、不可逆操作确认、多步歧义、压缩致技术歧义、用户困惑——此时不压缩；澄清后恢复。
4. **持久化产物豁免**：代码/注释/提交信息/PR/工单/文档/记忆文件一律正常行文（写给人看的产物不压缩）。
5. **压缩风格不压缩语言**：按用户主导语言回复，技术词/代码保原文。

## D077 反幻觉纪律

细则见 `references/anti-hallucination-rules.md`。要点：完成断言须新鲜证据；不确定即明示；冲突显式化；缺证据索引打回。

## 表达技巧：读最少文字、不失语义

> 面向**所有产出**（SKILL / references / 简报 / 交接包 / 提示词）。与 D080（prompt 撰写标准）互补：D080 管格式，本节管**信息密度**。

### 一、结构（提升可扫描性）

| # | 技巧 | 做法 | 反例 → 正例 |
|---|---|---|---|
| 1 | **结论前置** | 首行写可执行结论，理由后置 | 「由于 A、B、C，因此建议做 D」→「**做 D**（因 A/B/C）」 |
| 2 | **表格替散文** | 同维度对比一律表格 | 三段并列描述 → 一张表 |
| 3 | **一行一节** | 一节只说一件事，禁段落堆叠 | 长段含 3 个规则 → 3 行 |
| 4 | **编号即锚点** | 规则只在**一处**展开，别处引 `D0xx`/`R##`/`Pxx` | 复述规则全文 → 只写编号 |

### 二、用词

| # | 技巧 | 做法 |
|---|---|---|
| 5 | **约束用规范词** | 必须 / MUST / 禁止 / MUST NOT；**禁**「尽量/建议/最好/应该考虑」 |
| 6 | **禁修饰副词** | 删「//务必/进一步/充分地/有效地」（D080 ⑤） |
| 7 | **术语单形** | 同一概念全仓同一词（如统一用 `run-lead`，不换「工程主责/负责人」） |
| 8 | **删元话语** | 删「本文件…」「如上所述」「」——读者已知文件名与上下文 |
| 9 | **去名词化** | 「进行检查」→「检查」；「做出判断」→「判断」 |

### 三、冗余消除

| # | 技巧 | 判据 |
|---|---|---|
| 10 | **引用代替复述** | 同一规则全仓只展开一次；第二处起只给编号 |
| 11 | **示例即规格** | 一个可照抄的示例 > 一段自然语言描述 |
| 12 | **删连接词** | 删「因此/此外/综上/」——AI 不需过渡句 |
| 13 | **删总结段** | 正文已说清则不加「综上所述」 |
| 14 | **规格化否定** | 边界写成「禁止 X」而非「一般情况下不要 X」 |

### 四、反模式（禁）

| # | 反模式 | 原因 |
|---|---|---|
| 15 | 自造缩写/箭头替词（`cfg`、`→` 代「导致」） | D076：零节省且伤解码 |
| 16 | 同义复述凑长度 | 纯增 token，零信息 |
| 17 | 用描述代替规范 | 描述可争辩，规范可判定 |

### 五、动态加载判据（决定内容放 L0 还是 L1）

> **判据**：该内容在「当前阶段/当前岗位之外」是否会被读到？
> - 会被读 → 留 SKILL（L0 常驻）
> - 只在特定阶段/岗位读 → 移 `references/`（L1 按需），SKILL 只留一行指引 + 编号

实测收益（2026-09-13）：SKILL 32,720 → 28,180B（−14%），即按此判据移出 D074/D075/D076 细则所得。
