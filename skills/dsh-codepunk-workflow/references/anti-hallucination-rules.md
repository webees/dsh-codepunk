# 反幻觉纪律细则（references/anti-hallucination-rules.md）

> D077 按需展开（SKILL.md §2④ 只留指引，本文件为完整细则）。溯源：`benchmarks/anti-hallucination.md`（32 个来源，2026-08-26）。
> 目标不是「零幻觉」（官方明言不可消除），而是「可拦截、可追溯、可返工」。

## 一、完成断言 = 新鲜验证证据（Iron Law，全流程通用）

- 本消息内未运行验证命令（测试/构建/证据 log_ref），**不得声称「通过/完成」**。
- 红旗词：「应该能用 / 大概没问题 / 看起来完成 / should work / probably / seems done」——出现即触发证据回放（重跑命令或引用 log_ref）。
- 「agent 报告成功」不是证据：独立核 VCS diff / 构建产物 / 测试输出等物证。

## 二、不确定即明示（官方三件套）

1. **允许说「我不知道」**：显式授权承认不确定，比编造更优；「没有该记录/无法确认」是合法输出。
2. **事实引文接地**：声称事实须能直指文件/命令/URL；找不到引文即撤回主张。
3. **先查再定**：「不确定」前先查工具（搜索/命令/文件），查完再决定给证据还是回「不知道」。

## 三、知识冲突显式化

- 多段材料/多 agent 结论冲突 → 表层标注「冲突点（两处材料各称 X/Y）」，不悄悄选边。
- 需求确认与巡检阶段固定一问：「现有材料是否互相矛盾？」（防把冲突当作已解决）。
- 交接包 known_issues 中冲突遗留注明「未证实主张」（clarity-gate 限定性检查：带来源断言可入库，裸断言标注未证实）。

## 四、证据门控交付

- 交接包缺证据索引（command + exit_code + log_ref）→ **整包打回**，不进入签收。
- `evidence pass ≠ 可解散`：验收通过 ≠ 可宣布完成，还须交接包齐 + 签收。
- 高价值交付可加独立「护栏评审」：第二个模型按量化指标清单复核（precision/recall 度量）。

## 五、测试真实性（防空壳绿）

- sdet 除 `exit_code=0` 外，核查测试是否**真实断言**（防空壳测试/假测试/空测试）。
- 「绿」是行为信号不是表面信号：有失败路径的断言才算数。
- 评分时可加「测试非空壳」判定项。

## 六、上下文约束（防推断幻觉）

- 默认「基于材料而非通识」：材料缺口就报缺口，不拿行业惯例脑补填补。
- 长期记忆只收「确认过」事实（candidate-first）：知识库写入需证据背书或双人确认，未证实推断不得固化成规则。
- 上下文是有限注意力预算：陈旧/冗余上下文是幻觉诱因，持续剪裁（D074 同源）。

## 七、多智能体交叉验证（高危结论）

- 需求规格、最终验收等高危结论走「红蓝对抗」：一个 agent 找毛病、一个找证据支撑，结论并列进评分材料。
- 三人小组互证不互抄：测试只认代码行为、不认开发叙述。
- 门闩/签收/评分决策全部留痕（谁、何时、依据哪个 log_ref），供复盘追溯。
