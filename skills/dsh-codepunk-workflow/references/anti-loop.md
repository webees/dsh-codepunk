> 唯一权威来源：`benchmarks/anti-loop-research.md`（`retrieved_at: 2026-10-07`，机制编号 M1–M22、指标阈值、来源 URL 均在该文件）。本文件只做**落地映射**，不新增外部事实；凡本文件出现的量化数字，均可回溯到该研究文件。
> 内部实证补充：`benchmarks/loop-incident-inventory.md`（台账事故清册，2026-10-07 快照）。引用其数据时逐处标注该文件名。

> 与 D093（任务收口与子代理任务边界）同向：**子代理 MUST NOT 承载循环型目标**，收敛由主会话按轮驱动；本文件是主会话的轮内熔断细则。

## 一、适用范围与失效信号

本文件覆盖**六类可机械识别**的循环现象。判据口径与研究文件 §1 一致：信号 MUST 能从轨迹日志或对话内容机械判定，不依赖模型自述。

| 现象 | 可观测信号 | 首次出现时的最小动作 |
|---|---|---|
| 推理自重复 | 连续 3 步推理文本高度相似（n-gram 重合度超阈值）且无新工具调用、无新证据 | 停止复述，写出「当前假设、已证伪项、下一步不同做法」三行后再动作 |
| 无进展重试 | 同一失败指纹（命令加错误摘要）连续出现 2 次，错误信息实质相同 | 强制换策略并逐字记录换法，禁止第三次原样重试 |
| 工具调用风暴 | 同一（工具名，序列化参数哈希）指纹在 10 次窗口内出现 3 次，调用间隔稳定 | 在派发层计指纹并返回结构化拒绝反馈（错误码＋模式＋观测统计），不得静默拦截 |
| 验证循环 | 同一验证目标在输入未变（哈希未变）时被重复执行，结论未变化 | 走验证缓存，复用上次结论；重复验证须写明「自上次验证以来变化了什么」 |
| 计划-执行纠缠 | 计划文本版本数多于实际执行步数，或重规划次数与执行步数之比大于 1 | 冻结当前计划，只接受三类重规划触发条件，且重规划须附失败上下文 |
| 上下文污染循环 | 早先被证伪的结论在后文被反复引用并成为后续决策前提 | 立即标注「已证伪」并附证伪证据，清理该结论的原始引用，禁止作为推理前提 |

补充信号（来自内部台账清册，属**内部实测**而非外部研究）：环境陷阱重试循环（同一探针连续 2 次判 void 且原因同族）、管道吞退出码（判定语句在管道之后取 `$?`）、截断输出误判（判定所依据的输出被 `timeout`、`head`、`cut`、`tail` 截断）。三者见 `benchmarks/loop-incident-inventory.md` §五，与本节同属可机械判定类。

## 三、熔断阈值表

阈值口径取自研究文件 §4「可观测指标与阈值建议」，判定一律基于轨迹日志、可离线复算。**推断项**（研究文件未给数值、由本预设设定）在条目末标注「推测」。

| 阈值条目 | 判定方式 | 违反时写入何处 |
|---|---|---|
| 连续 3 步无新证据 | 逐步统计未产生新证据（新文件内容、新命令输出、新测试结果、新外部来源）的连续步数 | 台账 `ledger.md` 自纠行写自检三行；连续 5 步升级上报 run-lead |
| 同一失败指纹 2 次 | 同一「命令加错误摘要」指纹计数达 2 | 第 3 次拒绝该动作并返回结构化反馈；台账记换法与差异点 |
| 同参数工具调用 2 次 | 同一（工具名，序列化参数哈希）在同一任务内计数达 2 | 第 3 次须改参数、改工具或改策略，并在输出写明改变了什么 |
| 进度指针连续 4 步不变 | 关键产物哈希与进度指针快照连续 4 步无变化 | 停止当前路径，回退最近有效状态点，记入 `progress/` |
| 重规划与执行步数比大于 1 | 重规划次数除以实际执行步数 | 冻结计划，强制执行若干步后才允许重规划；记入简报的失败上下文 |
| 验证动作重复执行 | 同一验证目标在输入哈希未变时被再次执行 | 强制走验证缓存，记「自上次验证以来的变化」；无变化即不得重复验证 |
| 单步超时 300 秒（推测） | 单次工具调用挂钟时长达到该值（含 TOOL_TIMEOUT） | 改后台作业并降规模，登记实测耗时与产物路径；不得原样重跑 |
| 预算消耗速率超基线 3 倍（推测） | 单位时间 token 或费用消耗除以任务类型基线 | 降级模型或请求人工确认；记入台账自纠行 |
| 停滞预算占总步数 20%（推测） | 空转步累计量除以总步数预算 | 耗尽即安全停机并输出结构化诊断，上报 run-lead |
| 验证循环重复率大于 0 | 同一验证目标在输入未变时被重复执行的比例 | 视为浪费并记入台账自纠行；按「验证动作重复执行」条目处理 |

## 六、必要重复与空转的区分（防误杀）

本节与研究文件 §5 同源：熔断规则 MUST NOT 误杀正当重复，否则检测本身成为故障源。判定以「输入是否变化、错误指纹是否变化、是否有豁免」为准，不以动作外观为准。

| 场景 | 是否必要重复 | 区分判据 |
|---|---|---|
| 等待外部状态就绪的轮询 | 是 | 属白名单工具，且状态指针在推进或时间窗口明确 |
| 并发失败后的重试 | 是 | 失败原因不同（错误指纹变化）或退避策略在变化 |
| 修复后重跑测试 | 是 | 被测输入已变化（代码或数据哈希变化） |
| 同一测试连续重跑且输入未变 | 否 | 输入哈希未变、结论未变 |
| 同一搜索词重复检索 | 否 | 参数指纹相同、结果集相同 |
| 参数逐步收窄的探索式检索 | 是 | 参数指纹不同、结果集有新增 |
| 同一命令在失败后原样重试 | 否 | 错误指纹相同且无策略变化 |
| 编译类长耗时命令的重复调用 | 视情况 | 按工具设独立上限，不套用统一阈值 |

误杀风险与已知局限（研究文件 §5）：结构指纹会漏检语义相似循环，改用语义相似度则误报率上升；轮询与长耗时编译必须白名单豁免；硬上限只在预算耗尽后触发，属止损不属检测；只阻断不反馈会让模型原地打转；压缩会稀释硬约束，安全条款必须钉在不可压缩区域并逐轮重注入。

## 七、验收方式

以下条目均可机械核对，作为巡检与审查门的固定项：

1. 台账自纠行编号连续无跳号，且每行含「触发阈值条目＋换法＋差异点」三要素。
2. 每轮探针不得复用上一轮的命令集；同参数命令指纹在窗口内出现次数可由日志复算。
3. 每次修复必须同时给出红证（修复前失败命令与退出码）与绿证（修复后通过命令与退出码），缺一不得判通过。
4. 机制清单表每行的「落地位置」取值必须落在五种允许取值内，且 M1–M22 无缺号、无重复。
5. 交接包 MUST 含「已证伪的路径」字段，且不含被证伪结论的原始引用（防止接手方重复失败尝试）。
6. 子代理回传正文只含精炼摘要，失败轨迹原文不得出现在父会话上下文。
7. 表格列数一致、单元格内无未转义竖线；本文件与 `SKILL.md` 指针的章节名互相可解析。
8. 误杀回归：轮询与「修复后重跑测试」两类正当场景各跑一次，阻断模式下零误杀方可启用阻断。
9. 升级阶梯可复算：任一终止（阻断或停机）之前，轨迹中必先出现一次警告或换策略提示。

## 八、未决问题

1. 语义相似循环（同义改写参数的反复检索）尚无低成本可靠检测方案，现有实现明确不做（研究文件 §5 局限 1）——属已知盲区，**需实测**是否有可用的低成本近似判据。
2. 停滞检测（M17）在产物天然不变的任务上会误报，任务特定口径尚未定义——**推测**：可按任务类型登记豁免，但误报率未量化。
3. 停滞预算占总步数 20% 为研究文件的**建议值**，未在本仓负载上校准——**需实测**先以告警模式采集基线。
4. 进展预言机（M1）在探索性任务上难以定义，研究文件给出的代理指标（行为新颖性）信号强度未经量化验证——**需实测**。
