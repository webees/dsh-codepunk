# 文档政策

本文规定 dsh-codepunk 仓库内**文档的层级、权威顺序、同步义务与禁止项**。任何新建或修改文档（含 `README.md`、`CONTRIBUTING.md`、`docs/` 与 `skills/**` 下的 `.md`）都适用。

## 1. 文档层级与权威顺序

权威顺序**自上而下**；下层与上层冲突时，以下层为准的说法不成立——冲突即缺陷，须修下层并对齐上层。

| 序 | 层级 | 载体 | 读者 | 效力 |
|---|---|---|---|---|
| 1 | 硬规则与流程正文 | `skills/dsh-codepunk-workflow/SKILL.md` | 工程主责（主会话） | 最高；条款违反即红灯 |
| 2 | 按需细则 | `skills/.../references/*.md`（含 `standard.md` 编号释义、`stages.md` 阶段步骤） | 主会话按需加载 | 与 SKILL.md **同等效力**，冲突须当场收敛 |
| 3 | 开发与架构文档 | `docs/*.md`、`docs/adr/*.md` | 贡献者、接手者、部署方 | 解释性文档；不得与 1/2 冲突 |
| 4 | 使用者向概览 | `README.md` | 使用者与评估者 | 概述与命令表；冲突时以 1/2/3 为准并修正 README |
| 附 | 贡献者向公约 | `CONTRIBUTING.md` | 贡献者 | 提交门槛；**不复述目录清单**（唯一权威在 README） |

补充规则：

1. **编号唯一释义**：`Pxx` / `D0xx` 一律以 `references/standard.md` 为唯一来源，禁止引入该文件之外的编号引用。变更涉及编号时，**先登记 `standard.md`，再引用**。
2. **目录清单唯一权威**：目录与文件清单只在 `README.md`「目录结构」段维护一处；其他文档只引用不复述，避免两处各自漂移。
3. **调研档案独立**：`benchmarks/` 是调研与基准档案（含外部来源与检索日），不参与 `references/` 的规范效力，也不得被当作流程依据——需要据此决策时先补调研简报。
4. **运行状态不进文档**：运行根路径、任务 ID、subagent id 等属运行期状态，写入总库运行根，不落到仓库文档（示例一律用 `<project_id>` / `<run_id>` 占位）。

## 2. 改文档必须同步的三处

改任何流程文档前，先判断是否触及下表三处；触及即**同一提交内**同步，不允许「下一步再补」：

| # | 同步对象 | 位置 | 机械校验 |
|---|---|---|---|
| 1 | README 计数声称与硬规则上限 | `README.md` 质量工具表 / 计数文案 / 硬规则段落 | `doc-consistency.sh` 第 1 类（每处声称唯一且等于实况）、第 2 类（阶段口径） |
| 2 | 治理矩阵 | `references/skill-governance.md`「检查器覆盖矩阵」 | `doc-consistency.sh` 第 22 类（每个检查类须在矩阵中被提及，含「第 a–b 类」范围写法） |
| 3 | 决策登记表 | `references/standard.md` 的 `D0xx` 登记行 | `doc-consistency.sh` 第 9 类（D 号须逐条登记；P 号须落在已声明范围） |

延伸同步项（按改动内容判定）：

- 新增检查项 / 变异 → 同步 `checker-self-test.sh` 的 M 号与 README 声明计数（见 [development.md](development.md) §6、§7）。
- 新增目录或顶层文件 → 同步 README 目录结构段（`verify-battery.sh` 比对 README 目录树 ↔ 仓内跟踪文件）＋ 发布仓 `.gitignore` 白名单。
- 新增参照外部技能或基准 → 走技能治理三件套（简报 / 细则 / 溯源），见 `references/skill-governance.md`。

## 3. 禁止项

| # | 禁止 | 原因 | 校验者 |
|---|---|---|---|
| 1 | 三位及以上轮次号字面量（形如 `R` 加三位数字） | 与硬规则号 `R1–R17` 同形，会被误读；轮次引用一律写「轮次 N」 | `doc-consistency.sh` 第 19 类 |
| 2 | 本机绝对路径（用户目录、盘符、应用安装路径） | 泄露本机环境且不可移植；改用 `<DSH 安装根>`、`~/.dsh-codepunk/...` 等中性写法 | 泄露防护门通用模式 |
| 3 | 表格列数与表头不一致 / 数据行单元格多于表头 | GFM 下多余单元格被静默忽略，内容悄悄丢失 | `doc-consistency.sh` 第 24 类 |
| 4 | 代码跨度内的竖线未转义（应写作 `\|`） | 在表格中被误判为列分隔，破坏列数判据 | `doc-consistency.sh` 第 24 类 |
| 5 | 分隔行后紧跟空行 | 断表：表体被判为正文，表格失效 | `doc-consistency.sh` 第 24 类 |
| 6 | 非 ISO 日期形态与未来日期 | 「实测」不能发生在未来；形态不统一则时效性判据失效 | `doc-consistency.sh` 第 8 类 |
| 7 | 未登记的 `D` 号、越界的 `P` 号 | 编号引用不可解析 | `doc-consistency.sh` 第 9 类 |
| 8 | 指向不存在章节的 `§N`，或 `references/<名称>.md「章节名」` 的标题在目标文件中不存在 | 章节级引用悬空 | `doc-consistency.sh` 第 10 类 |
| 9 | 仓内相对链接死链 | 读者可见缺陷 | `preset-audit.sh` E3 |
| 10 | 含 URL 却不带 `retrieved_at` 的简报 | 来源不可追溯 | `doc-consistency.sh` 第 23 类 |
| 11 | 状态值越界或只存在于模板注释的死状态 | 状态机不自洽、无主体 | `doc-consistency.sh` 第 12 / 13 类 |
| 12 | 私有 provider / 模型取值、密钥、邮箱、私网地址 | 公开仓库不得含私人化信息 | 泄露防护门（禁词留本地） |
| 13 | 仓内不存在的路径引用（含把仓外/运行根产物写成仓内形态，如给仓外工具加 `plans/` 前缀） | 公开仓读者不可解析；域或扩展名漏项即长期零守护（F408） | `doc-consistency.sh` 第 4 类（域＝全部跟踪 `.md`；扩展名 `sh\|py\|mjs\|cjs\|ps1`） |

关于第 2 与第 12 条：**中性写法**指 `<DSH 安装根>`、`<profile>`、`~/...`、`<project_id>`、`<run_id>` 这类占位表达；需要指向本机具体位置时，写清「取环境变量」（如 `DSH_APP_ROOT` / `DSH_PROFILE_PATCH`），而不是写死取值。

## 4. 写作规范

1. **语言**：中文；对内（思考、草稿、评审、汇报）与对外文档一致使用全角标点（，。；：（）），禁以精简为名删标点；代码、命令、路径、标识符保留原样。
2. **结构**：标题层级从 `#` 起逐级下探，不跳级；每篇文档首段说明读者与定位；表格用于对照与枚举，命令示例用围栏代码块并标注语言。
3. **可核验**：涉及数字、计数、上限的表述一律**派生**（给出派生命令）或标注来源；不确定处写「见 `plans/<名称>.sh` 实况」或省略，禁止声称未实现的能力。
4. **时效标注**：实测类结论须带日期（ISO 形态）；跨版本结论须注明适用的 DSH 版本（应用版本与 CLI/包版本是两套编号，勿混用）。
5. **提示词类正文**：`references/roles.md` 的派遣模板等 prompt 正文遵守撰写标准——节名用方块标签【节名】、不在 prompt 正文用 `##` 标题、一行一节、每节不超过 40 字且动宾起头、禁修饰副词。
6. **表格**：表头与分隔行同时写全；单元格内换行用 `<br>`；代码跨度内含竖线一律转义。
7. **图片与配图**：需要配图时按场景选型（流程 → Process、分块依赖 → Dependency、交接 → Data flow），遵循 4px 网格与语义配色；静态图优先，避免引入构建依赖。

## 5. 写作与质检留痕

文档小组产出按**三帽折叠**推进：同一席可依次承担文档主责、技术写作、文档质检三种角色，但**必须留痕**：

| 标记 | 含义 | 位置 |
|---|---|---|
| `role: tech-writer` | 本条内容由技术写作角色撰写 | 产物头部或运行根记录 |
| `checked_by: docs-qa` | 已由文档质检角色核对（口径、编号、列数、来源） | 同上 |
| `docs-lead`（签发） | 简报类产物经工程主责批准后才是签发版本 | 简报批准字段 |

未过质检的文档不得作为交接包内容，也不得用于对外发布。

## 6. 文档改动自检清单

- [ ] 新增/修改的文档已归位：流程正文进 `SKILL.md`、细则进 `references/`、开发与架构进 `docs/`、概览进 `README.md`。
- [ ] 涉及计数、机制、阈值时，已同步 README、治理矩阵、`standard.md` 决策登记表（如触及）。
- [ ] 无三位轮次号、无本机绝对路径、无私有取值。
- [ ] 表格列数一致，代码跨度内的竖线已转义，分隔行后无空行。
- [ ] 日期为 ISO 形态且非未来；实测结论带日期。
- [ ] 相对链接可达（仓内路径存在）；文中提到的 `plans/*` 引用均真实存在，仓外（运行根）产物已显式标注且未写成仓内形态。
- [ ] `bash plans/doc-consistency.sh` 返回 0（或红项已定位归属）。
- [ ] 产物已标注 `role: tech-writer` / `checked_by: docs-qa`（协作产物）。
