## 1. ADR 模板

### 1.1 命名与编号

| 项 | 规则 |
|---|---|
| 文件名 | `docs/adr/<四位数序号>-<短标题>.md`，短标题用小写连字符（如 `0001-record-architecture-decisions.md`） |
| 序号 | 从 `0001` 起单调自增；**不复用、不跳号**（废弃的 ADR 仍占号，状态改为「已废弃」） |
| 标题 | 文档内一级标题写 `ADR-NNNN：<中文标题>`，与文件名语义一致 |

### 1.2 状态取值

| 状态 | 含义 |
|---|---|
| 提议 | 已写出，尚未获得决策 |
| 已接受 | 决策生效，实现与文档须与其一致 |
| 已废弃 | 不再适用，但不被其它 ADR 取代 |
| 被取代 | 由后续 ADR 取代，须写明取代者编号 |

### 1.3 必填字段

```markdown
# ADR-NNNN：<标题>

- 状态：<提议 | 已接受 | 已废弃 | 被取代 by NNNN>
- 日期：YYYY-MM-DD
- 决策者：<谁决策>
- 影响面：<哪些文档 / 脚本 / 配置会受影响>

## 背景
<问题、约束、触发事件；引用实测证据>

## 决策
<做了什么决定，可执行、可核验>

## 后果
<正面影响 / 代价 / 边界与已知缺口>

## 替代方案
<被否决的方案与否决理由>

## 参考
<相关文件、编号、命令>
```

### 1.4 写作规则

1. **一条 ADR 只记一个决策**；决策须可核验（能指向命令、文件或判据）。
2. 结论优先：背景控制在必要限度，不用叙事代替结论。
3. 涉及编号的决策，先在 `references/standard.md` 登记 `D0xx` 再在本文件引用。
4. 本文件受 [../documentation-policy.md](../documentation-policy.md) 约束：中文、全角标点、表格列数一致、代码跨度内竖线转义、禁本机绝对路径、禁三位轮次号。
5. 新增 ADR 的流程：复制 §1.3 骨架 → 顺延编号 → 写决策 → 与仓库一致性门禁一起跑（`bash plans/doc-consistency.sh`）。

## 2. ADR-0001：写盘纪律以预设层三层强制为主、宿主层为辅助

> 本 ADR 记录的是**此前已生效的纪律的架构定性**（原表述散见于硬规则与细则文件中，本文将其固化为一条可引用的决策）。

### 2.1 状态

- 状态：已接受
- 日期：2026-10-07
- 决策者：流程主责（工程主责）与文档小组联署
- 影响面：`SKILL.md` 写盘纪律条款、`references/file-hygiene.md` §六 / §7、`plans/write-scope-check.sh`、各岗位写域

### 2.2 背景

1. **宿主沙箱的粒度不足**：宿主侧的机械写盘强制只能覆盖「会话 cwd + 系统临时区」，可写白名单实际只有三处（会话 cwd、`/tmp`、`os.tmpdir()`），且**无多可写根**扩展。而本流程需要三处**互异**落点——运行根、授权工作树内该任务的写集、总库知识库。
2. **宿主层可能未生效**：运行时策略由用户平面的 `defaultPreset` 决定；当它取宽值时，本机**没有任何宿主写盘限制**。
3. **宿主不认识授权写集**：宿主不识别「授权工作树 `write_paths`」这一概念，跨工作房写入不会被告警；文件写集在本仓属**约定强制**（人设自律 + 审查门 `diff ⊆ write_paths` + 工作树隔离），不是沙箱。
4. **历史教训**：临时物落工程工作树、`$HOME` 顶层散落、系统目录自建物，会造成 diff 污染、归属不明与归因错误（把他人残留记到本工程头上）。

### 2.3 决策

写盘纪律采用**三层强制，预设层为主、宿主层为辅**：

| 层 | 载体 | 角色 |
|---|---|---|
| 硬规则层 | `SKILL.md` 的写盘纪律条款（R17） | 声明四优先序与禁令清单 |
| 判据权威层 | `references/file-hygiene.md` §六（白名单 / 黑名单 / 越界判据）、§7（宿主层现状与缺口） | 定义判据与归属语义 |
| 机械门层 | `plans/write-scope-check.sh` | 实跑判定：0 通过 / 1 越界 / 2 无法核验 |
| 宿主层（辅助） | 宿主沙箱策略与审批 | **可选启用，粒度到会话 cwd 与临时区，不得替代上述三层** |

配套决定：

1. 落点四优先序：运行根 → 授权工作树内该任务写集 → 系统临时目录（次选，用毕即删）→ 总库 `knowledge/`。
2. **越界即缺陷**：当轮清理并在运行根 `README.md` 的 `write_scope:` 段记台账；未清理不得进入交接门与合并门。
3. 探针与补丁脚本一律落运行根 `logs/`，命名 `probe-r<轮次>-<用途>.sh` / `patch-r<轮次>-<用途>.py`。
4. 预设与子代理 **MUST NOT** 擅自修改用户平面的权限配置——那是人类环境决策；只能以「建议 + 片段 + 影响面 + 生效方式」四件套提交裁定。
5. 不得以「宿主沙箱会拦」为由省去本节纪律；即便宿主层已启用，其覆盖面与四优先序**不等价**。

### 2.4 后果

正面：约束始终在岗（不依赖宿主配置）；判据可机械复跑；越界有归属语义（契约命名空间优先，他人同形残留降级为「归属不明」而不误判）。

代价与边界：纪律靠人设与审查维持，属**约定强制**而非沙箱强制；临时区禁写做不到（宿主语义上必然包含临时区），只能靠收尾机械门发现残留；若会话 cwd 为 `$HOME` 或其祖先，`$HOME` 顶层散落在宿主白名单内，仍须靠纪律与机械门兜底。

### 2.5 替代方案

| 方案 | 否决理由 |
|---|---|
| 只靠人设自律 | 无机械判据，越界不可发现，历史上已多次复发 |
| 只靠宿主沙箱 | 粒度不足（无多可写根、不识别写集），且可能整体未生效——等于无约束 |
| 宿主与预设并重为双主 | 两套判据互相推诿，冲突时无从裁决；且宿主层选项随环境变化，不宜作承重 |
